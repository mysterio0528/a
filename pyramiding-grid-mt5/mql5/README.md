## 2. 導入手順

1. `PyramidGridE.mq5` を `MQL5/Experts/` に配置し **MetaEditorでコンパイル**
   （本コードはコンパイラ未到達環境で書かれている。警告/エラーが出たら都度修正）
2. **ヘッジング口座**であることを確認（ネッティングでは起動拒否する）
3. **ストラテジーテスター**（モデル: 全ティック/リアルティック）で最低3ヶ月回す
   - 確認項目: ブリック数、モード遷移ログ、バスケットTP/予算ストップ回数、
     ダッシュボードの χ_eff（**0.10超なら d を広げる**: v0.2規律）
4. デモ口座で1〜2週間フォワード → 死体撃ち・リシンク（EA再起動）・CloseBy挙動を確認
5. 実口座は最小ロットから。`予算ストップ1回の損失 = InpBudgetD × d × ロット価値`
   が口座の1%以下になるロットで開始（RESEARCH_NOTE §9のロット式）

## 4. 既知の制約・simとの相違（正直に）

- **未コンパイル**: MetaEditorでの検証が必須（API名・シグネチャの最終確認）
- 成行方式のため検出〜約定のオーバーシュートを払う（ダッシュボードでε̂を実測表示。
  これはsimのχに織り込み済みの量であり、χ_eff監視で管理する設計）
- ニュースカレンダーフィルター（E6）は未実装（スワップ日・金曜フラットのみ）。
  MQL5経済カレンダーAPIでのPhase 2追加候補
- 動的dはATR床のみ（チョップ実測振幅×1.3の完全版はPhase 2）
- 1秒未満の連続ブリック（ギャップ）は同一tick内で逐次処理されるが、約定価格は
  その時点の市場価格になる（simも同様の保守的扱い）
- Strategy Tester使用時: `Sleep()`は無視される／状態ファイルはテスター砂箱に作られる

## 5. 監視ダッシュボード（チャート左上）

- `mode` / `run` / `alt`: 状態機械の現在地
- `盤面` vs `目標/予算`: バスケット会計（実現+含み）
- `p̂(継続)`: 自己約定列からの継続確率オンライン推定（6.3章のエッジ生死メーター。
  **長期に p̂ < 0.5 の商品・時間帯では稼働させない**）
- `χ_eff`: スプレッド+手数料+実測オーバーシュートのコスト比。**0.10超は設計違反**
- `棄権`: ゲート/モードで見送ったブリック数（E仕様では多いのが正常。sim比77-84%）
