## 0. TL;DR — 5つの発見

1. **設計書v0.1の代数に誤りがあった（訂正済み）**: ヘッジペアのロック損失は `−d − 2c_rt`（c_rt=1ポジ往復コスト、つまり片道コストcの表記では `−d − 4c`）。v0.1は半分に過小評価していた。訂正後の損益分岐は**ランダムウォークで厳密にマイナス**となり、「状態選択だけがエッジの源泉」というテーゼがより強固になった。
2. **素の仕様（変種A）は「グリッド幻想」を定量的に再現する**: 純粋ランダムウォーク上で実現損益 +15,137d を稼ぎながら、エクイティは −10,174d、最大保有223ポジ。**実現損益カーブは常に右肩上がりに見えながら破滅する** — 含み損を見ない運用報告が詐欺的に見える理由そのもの。
3. **線形ガバナー（D）は出血を1/20に抑えるが黒字化はしない。モード状態機械（E）だけが黒字化する**: トレンド持続性を振った全実験で D は全域マイナス、E は全域プラス。差は (a) CHOP検知時の完全棄権、(b) TREND検知時のガバナー解除＋全面トレイル参加、(c) 滓の直接クローズ。**「制御の追加」ではなく「参加の非対称化」が戦略の本体**。
4. **反転幅 2d（標準Renko化）は最大の単一改善**: E政策で +191d → **+1,769d（9倍）**、DD減。議論ポイント②は「採用」で確定推奨。
5. **バックテスト方法論の罠を定量化**: コストゼロのマルタンゲール上でストップグリッドが +0.029d/brick の「見せかけのエッジ」を持つ。正体はオーバーシュート（≈0.58×tickσ、Siegmund理論と一致）で、**実運用ではストップ約定のスリッページとして支払う**。mid価格レンコでのバックテストは系統的に過大評価する — 実tickからオーバーシュートを測り χ に算入せよ。

## 1. 訂正（Errata v0.1 → v0.2）

| 箇所 | v0.1 | 訂正 |
|---|---|---|
| ペア恒等式 | `−d − 2c`（c=片道） | **`−d − 2c_rt = −d − 4c`**（2ポジ×往復） |
| チョップ1往復のロック | `d + 2c` | **`d + 2c_rt`**（ブリックあたり `(d+2c_rt)/2`） |
| 損益分岐の例示 E[L]>1.90 | RWのE[L]=2.0より下＝「ランダムでも僅かに勝てる境目」 | 訂正後は**RWで厳密に負**。コストゼロ・ρ=1でのみ期待値0（マルタンゲール整合）。シミュレータで数値検証済み |

検証済みの正しい損益分岐（ペア即時ロック会計、i.i.d.近似）:

```
p* = (1 + 2χ) / ((1 + ρ) + χ)        χ = c_rt / d（コスト/グリッド幅比）
E[PnL/brick] = [ p(ρ − χ) − (1−p)(1 + 2χ) ] / (2 − p)   （d単位）
```

- χ=0, ρ=1, p=0.5 → 期待値ゼロ（無裁定整合 ✓）
- p* は χ と ρ だけの関数。**χ ≤ 0.10 が設計規律**（χ=0.10, ρ=0.9 → p*=0.632 / χ=0.04 → p*=0.557）
- ただし p* は「TP回転コア」の分岐点。モード機械（トレイル参加）の実証フロンティアはこれより低い（§6）

p_trend（トレンドレジーム内の継続確率）を 0.576→0.711 まで振り、D と E の損益（/1000ブリック, ρ=0.9, d=20bps）:

| p_trend | D (χ=0.04/0.07/0.10) | **E (χ=0.04/0.07/0.10)** | E の最大DD |
|---|---|---|---|
| 0.576 | −34 / −34 / −43d | **+43 / +38 / +33d** | 122–130d |

- **E は理論 p*(χ) より低い p_trend でも黒字** — p* はTP回転の分岐点であり、トレイル参加の経済（捕捉 ≈ (L−2)(L−5)/2 × d/run、L≥5で正）と棄権がそれを下回らせる

| 政策 | r=1（現仕様） | r=2（標準Renko） |
|---|---|---|

**全政策で改善、Eでは9倍**。1d反転は「振幅dのチョップに最大感度で被弾する」設計であり、反転確認に2dを要求するだけでブリック列自体の質（p 0.47→0.60）が変わる。**推奨: 反転側ストップは2d（少なくともTREND/NORMALで）。トレンド初動の1d分の遅れは対価として安い。**

## 8. 方法論の罠: オーバーシュート＝スリッページ

- ブリック確定は「価格が閾値を超えた瞬間」だが、超えた瞬間の実価格は閾値より平均 ε ≈ 0.58σ_tick 先にいる（Siegmund近似、実測一致）
- mid/last価格のレンコ・バックテストはこの ε を**毎約定の追い風**として計上する（マルタンゲールで+0.029d/brickの偽エッジ）。実際のストップ注文は ε を**スリッページとして支払う**
- **処方**: Phase 1 で実tickのオーバーシュート分布を測定し、χ_eff = (spread + 2×手数料 + ε̂)/d で評価。tick速度が上がる（σ_tick増）ほど ε も増える — R6（ボラ爆発）でストップが滑る現象の定量モデルそのもの

## 9. チョップ予算の具体計算（ロット上限式）

チョップ1方向転換 = 1ペア相当 = (1+2χ)d のロック。エピソードあたり転換数の95%点 n95 を使い:

```
ロット上限 = リスク予算 / ( n95 × (1+2χ) × d × 契約サイズ )
予算ストップ採用時:  1リセット損失 = budget_d × d × 契約サイズ × ロット
```

例（XAUUSD, d=$3.2≒20bps@3500ドル想定でχ=0.1, 1lot=100oz）:
- world1並みの苛烈チョップ（n95=147）: 147×1.2×3.2×100 ≈ **$56,400/lot** → 口座10万ドル・予算5%なら **0.09 lot**
- world2並み（n95=21）: ≈ $8,100/lot → 0.62 lot
- 予算ストップ20dなら1リセット = $6,400/lot → リセット1%制限で 0.16 lot
→ **実データの n95 がロットを決める**。これがPhase 1の測定項目に入っている理由。

## 10. 設計書への反映（確定事項）

1. **モード状態機械はオプションではなく戦略コア**（設計書6章の位置づけを格上げ）。優先実装順: CHOP棄権 → TRENDトレイル → ガバナー → ペア/バスケット/予算
2. **反転幅 2d を採用**（モード別微調整は Phase 2）
3. ρ（TP/d）は回転コアの脇役: 0.9 目安。**主たるαはトレイルにある**
4. ロック=実現損会計・予算リセット制度: シミュレーションで全変種のDDを有界化したまま機能することを確認。採用確定
5. χ 設計規律: **d ≥ 10 × (spread + 2×手数料 + ε̂)**
6. グリッドは**mid基準で定義し、発注時にbid/askへ変換**（buy stop=mid+s/2, sell stop=mid−s/2 相当）— さもないと反転側の実効距離が d−s に縮み、チョップ感度がさらに悪化する（設計書8章に追記）

## 11. 残課題と限界（正直に）

- **合成世界のレジーム滞在は長め**（トレンド平均 ≈ 数十〜百ブリック）。実市場の20bpsブリック尺度でのレジーム滞在長は未知 — **Eの数字は上界寄り**。Phase 1 で「rolling p̂ の滞在時間分布」を必ず測ること
- 本セッションのネットワークポリシーで実データ取得が遮断されたため、Phase 1 は未実施。`fetch_binance.py`（BTCUSDT 1s klines）と `fetch_dukascopy.py`（XAUUSD 実bid/ask tick→スプレッド時間帯分布も測れる）を手元で実行すれば、`renko.py`/`run_study.py` がそのまま実データで回る
- θ_b（バスケット目標）/budget_d/ガバナー係数は未調整の初期値。E の頑健性（パラメータ感度）確認は Phase 2
- 検出ラグ3ブリックの固定値、CHOP検出の交互3連鎖も同様に感度未調査
- 業者執行（ストップレベル、リクオート、CloseBy可否）は実弾でのみ検証可能
