## 0. 記号定義と基本仕様の確認

| 記号 | 意味 |
|---|---|
| `P_a` | アンカー価格（最後に約定したグリッド価格） |
| `d` | グリッド幅（アンカーから上下の逆指値までの距離） |
| `c` | 片道実効コスト（スプレッド/2 + 手数料 + 期待スリッページ） |
| `k` | TP倍率（TP幅 = k × 往復コスト 2c） |
| `ρ` | TP/d 比率（ρ = TP幅 / d）。挙動を質的に決める最重要比率 |
| `B, S` | 保有buy数 / sell数 |
| `D` | ネットデルタ = B − S（ロット均一前提） |
| `G` | グロスポジション数 = B + S |
| `L` | ランレングス＝同方向の連続約定数（後述、本戦略の生命線） |
| `η` | 滓（おり＝逆行含み損ポジ）の最終回収率 |

### 基本仕様（ユーザー定義）の動作整理

1. 現在価格をアンカー `P_a` とし、`P_a + d` に buy stop、`P_a − d` に sell stop を1個ずつ置く
2. 各ポジションは TP = k × 2c で利確
3. 逆指値が約定したら、その価格を新アンカーとし、上下の逆指値を置き直す

この仕様の帰結（設計上の自覚事項）:

- **上昇継続** → buy stop が連続約定し、buyが積み上がる（ピラミッディング）
- **d 逆行** → 反対方向の stop が約定。このとき直前のポジとの間に**ヘッジペア**が成立する
- アンカーは常に「最後の約定価格」なので、本質的に **値幅 d の全方向追従（SAR的）構造**

## 1. 戦略の数理的本質 — 全制御設計の土台

### 1.1 この戦略は「1ブリック反転Renko」と等価である

アンカー更新ルールにより、約定イベント列は **ブリック幅 d、反転幅 d のRenkoチャート**と1対1対応する。

- 同色ブリック連続（上→上→上…）＝トレンド ＝ buy連続約定
- 色反転（上→下）＝ d 逆行 ＝ 反対stop約定 ＝ ヘッジペア成立

**含意1（検証が劇的に簡単になる）**: tickデータを d-Renko 列に変換すれば、戦略の損益は「ブリック色系列」の関数に完全に帰着する。OHLCバックテスト不要で、**ランレングス分布（同色連続長 L の分布）を測るだけで期待値が出る**。

**含意2（標準Renkoより脆い）**: 標準Renkoは反転に2ブリック（2d）必要だが、本仕様は1d逆行で反転する。つまり**振幅dちょうどのチョップに最大感度で被弾する**設計。これは後述の非対称化（反転側 stop を 1.5d〜2d に置く）の検討理由になる。

### 1.2 ヘッジペアの損失は「含み損」ではなく「確定損」である

buy @ `P+d` と sell @ `P` のペアの合計損益は、現在価格 x に対して:

```
PnL_pair = (x − (P+d)) + (P − x) = −d        （コスト込みで −d − 2c_rt = −d − 4c）
```

**価格がどこへ行こうとペア合計は −d − 2c_rt で固定**（2ポジ×往復コスト。v0.2訂正）。つまり:

- レンジで1往復するごとに、確定的に `d + 2c_rt` の損失がロックされる（＝レンジ蓄積コスト）
- これは「含み損＝必要経費」という曖昧な会計ではなく、**発生時点で実現損として計上すべき確定費用**
- 「次のトレンドで救済される」のは**ペアになっていない側の滓だけ**。ペアは何があっても戻らない

> 設計原則①: ロック損失を実現損益と同じ勘定で管理し、希望を持たない。
> 「必要経費の上限」は曖昧な含み損総額ではなく、**累積ロック損失額**で定義できる。

### 1.3 マスター方程式 — 期待値の構造

ランレングス L のラン（同方向連続約定）は、ρ ≤ 1（TP幅 ≤ d）の場合:

- 先頭の L−1 個は利確される: 各 `+ρd − 2c`
- 末尾の 1 個は反転を食らい滓化する: 最終的に `−(d + 2c) × (1 − η)` のコスト（η は救済・回収率）

期待値（1ブリックあたり）:

```
E[PnL/brick] ≈ (1 − 1/E[L]) × (ρd − 2c)  −  (1/E[L]) × (d + 2c)(1 − η)
```

**損益分岐条件**:

```
E[L]  >  1 + (d + 2c)(1 − η) / (ρd − 2c)
```

この式が本戦略のすべてである。全制御はこの3変数の操作に帰着する:

| 変数 | 意味 | 対応する制御 |
|---|---|---|
| `E[L]` を上げる | トレンド性の高い場所・時間でだけ回す | エントリー制限、レジーム検知、セッションフィルター |
| `η` を上げる | 滓の回収率を上げる | ペア決済、バスケットTP、滓の層管理、「次のトレンドで解消」 |
| `ρ, d` の適合 | 場のボラ構造にグリッドを合わせる | 動的 d、動的TP、非対称グリッド |

数値例（XAUUSD想定: spread+手数料 ≒ 2c = 25¢、d = $2.0、ρ = 0.75 → TP = $1.5、η = 0.5）:

```
損益分岐 E[L] > 1 + (2.0 + 0.25)(0.5) / (1.5 − 0.25) = 1.90
```

→ **平均ランレングスが約1.9ブリック以上の市場状態でだけプラス**。完全ランダムウォークの E[L] は 2.0（境界ぎりぎり）なので、コスト構造次第で「ランダムでも僅かに勝てる/僅かに負ける」の境目にいる。**エッジは『E[L]が高い状態を選別する制御』そのものから生まれる**。これが参考テキストの「トレンド頻度×振幅 > レンジ蓄積コスト」（疑似ロングストラドル仮説）の正体。

### 1.4 オプション複製としての解釈

本戦略は**ロングストラドルの離散複製**である:

- トレンド（大きな実現ボラ）で利益 ＝ ロングガンマ
- チョップで d+2c ずつ確定損 ＝ 支払いプレミアム（セータ相当）

ゆえに本戦略の敵はボラ低下ではなく、**「振幅 ≒ d のチョップ」という特定周波数のノイズ**。逆に最良の友は「ボラ収縮 → 一方向ブレイク」。この性格は逆張りリミットグリッド（ショートガンマ、レンジで稼ぎトレンドで死ぬ）と正反対であることを常に意識する。

## 2. 状態空間の定義 — 「あらゆる状態」を3軸テンソルで張る

状態 = **市場レジーム × 盤面（インベントリ）状態 × 口座状態** の直積。

### 軸1: 市場レジーム（7分類）

| ID | レジーム | 定義（自己約定ベース） |
|---|---|---|
| R1 | 強トレンド | 同色ラン L ≥ 4、利確回転高、tick速度高 |
| R2 | 弱トレンド | ネットで一方向だが反転混じり（色比率 7:3 程度） |
| R3 | 広域レンジ | 振幅 ≫ d、数ブリック進んで反転を繰り返す |
| R4 | チョップ | 振幅 ≒ d〜3d、色交互（BSBS…）、最悪状態 |
| R5 | ボラ収縮 | 振幅 < d、約定が発生しない |
| R6 | ボラ爆発 | 指標・ギャップ・フラッシュ。単位時間あたり約定数異常 |
| R7 | レジーム遷移 | R5/R3→R1（ブレイク）、R1→R3（失速）、R1→R1'（V字反転） |

### 軸2: 盤面状態（5次元）

1. **ネットデルタ D** = B − S: 中立（|D|≤2）/ 偏り小 / 偏り大（|D|>n_max）
2. **グロス G** = B + S: 軽い / 中 / 重い / 上限近傍
3. **損益分布**: 盤面合計プラス / 微マイナス / 大マイナス、および「実現+ロック」勘定の水準
4. **滓の層構造**: 現在価格の上方に堆積したbuy滓・下方のsell滓の価格帯分布（後述4.3）
5. **ヘッジ率**: min(B,S)/max(B,S)。1に近い＝ロック化が進行、0に近い＝方向ベット

### 軸3: 口座状態

- 証拠金使用率（4段階: <50% / 50-70% / 70-85% / >85%）
- 「実現+ロック」累積のドローダウン深度（盤面リセット予算に対する消化率）
- キャリーコスト累積（スワップ/ファンディング）

以降、セクション3で軸1（市場）を、セクション4で軸2-3（盤面・口座）を展開する。実際の制御は両者の交点で決まる。

## 3. 市場レジーム別: 想定 → 仮説 → 制御

### S1: 強トレンド（R1）× 盤面任意

**想定する状況**: buy stop（上昇時）が連続約定。L ≥ 4。各ポジは順次TP到達。最良の状態であり、α の唯一の源泉。

**仮説**:
- 本戦略の年間損益は「数回の大トレンドをどれだけ逃さず取り切ったか」でほぼ決まる（ストラドル買いの損益構造の必然）
- 固定TP（k×2c）はトレンドの尻尾を捨てる。**S1でのみ利確方式を変えるべき**
- 逆側stopは押し目で約定して滓を作るが、同時にV字反転への唯一の保険でもある → 撤去ではなく距離調整が正解

**制御**:
1. **TPのトレイル化**: S1検知中の新規ポジはTP指値を撤去し、トレイリング（例: 直近ブリック2個分 = 2d を追従幅）に切替。既存含み益ポジも移行
2. **非対称グリッド**: 順方向stopは d のまま、逆方向stopを 1.5d〜2d に拡張（押し目ノイズで滓を作らない。標準Renko化）
3. **ロット漸増の抑制**: ピラミッドの増し玉は等ロット維持（上限あり）。漸増はV字での加重平均点悪化が激しく、破滅モードを作る
4. **滓の救済予約**: トレンド方向と逆の既存滓（上昇トレンドなら下方sell滓）は含み損拡大中。新規利確益との**ペア決済（CloseBy）を自動マッチング**し、トレンド利益で滓を順次焼却（η引き上げの主機構）
5. S1中は間引き（損切り）を抑制 — トレンドは滓の救済チャンスでもあるため、確定損での処理はもったいない。ペア決済優先

### S2: 弱トレンド（R2）

**想定する状況**: 方向は出ているが d 以上の押し戻りを伴う。buy利確とsell滓化が混在。ネットでは僅かにプラスだが、滓が「澱」のように溜まり始める。

**仮説**:
- 中期成績は S2 での滓処理の巧拙で決まる（S1は誰でも勝て、R4は誰でも負ける。差がつくのはここ）
- 押し戻りで成立する逆方向ポジは、(a) トレンド再開で滓化する一方、(b) トレンド終端では先回りポジになる。**事前にどちらか判定する手段はないので、事後の処理ルールで期待値を作る**

**制御**:
1. **利益の税金方式**: 実現利確が出るたびに、その β%（初期値30%）を「間引き予算」に積み、予算内で最悪滓（後述スコア順）を処理
2. **ペア決済の常時マッチング**: 含み益ポジ1 + 含み損ポジ1 の合計が `+ε` 以上になる組合せを常時探索し、成立したら即実行（1:1原則。1益で複数損を消す方式は比率が崩れ少数派保護が壊れるため禁止 — 参考テキストの警告どおり）
3. **逆方向エントリーの一段抑制**: R2判定中、逆方向stopは約定後の再設置までのクールダウン（例: 次のブリック確定まで再設置しない）を入れ、押し目1回での滓量産を防ぐ

### S3: 広域レンジ（R3）

**想定する状況**: 数ブリック（3〜8d）進んでは反転。レンジ端で積んだポジが反対端で最大含み損。中央回帰で一部救済。buy滓がレンジ上部に、sell滓が下部に堆積していく（順張りグリッド特有の堆積パターン。逆張りグリッドと逆）。

**仮説**:
- レンジの存在と端の位置は、**自分の滓の堆積分布そのものが写像している**（buy滓の密集帯 ≒ レンジ上端、sell滓密集帯 ≒ 下端）。外部インジより自己盤面が正確
- レンジ端では「逆方向の約定」が予告なく起こるので、端の推定ができれば (a) 端方向への新規を抑制、(b) 端での反転を滓救済（中央回帰時にペア決済）に利用できる
- 広域レンジは振幅があるため、**端の判定さえできれば中立〜微益で生き延びられる**。問題は次のR4

**制御**:
1. **約定列によるレンジモード判定**: 直近の色系列が「3〜8連続→反転」を2回以上繰り返したらR3へ遷移
2. **滓ヒートマップによる端推定**: 価格帯ごとの滓数を集計し、現在価格が滓密集帯（推定端）に接近したら、その方向の新規stopを休止 or 距離を倍化
3. **中央回帰での清掃**: 推定レンジ中央への回帰時、救済された側の滓を含み益化した時点で順次ペア決済。**バスケットTPの目標を下げて（後述）小さく盤面リセット**する選択も持つ
4. d を「推定レンジ幅 / 4〜6」へ動的調整し、端まで2〜3ブリックで到達する解像度を保つ

### S4: チョップ（R4）— 最重要・最悪状態

**想定する状況**: 振幅 ≒ 1〜3d の往復。BSBSBS…の交互約定。**1往復ごとに d+2c が確定ロック**。ヘッジペアの山が積み上がり、グロスだけが膨らむ。利確はほぼゼロ。

**仮説**:
- 本戦略の死因の第1位。ただし損失は確定的・線形（指数的ではない）なので、**「何往復まで許容するか」は純粋な予算問題として事前に決められる**
- チョップは利確回転の消滅として最速で観測できる（インジより速い）。参考テキスト冒頭の「決済数に応じたエントリー制限」が構造的に最強の防御である理由: **ロジックが機能している証拠（利確回転）がない限りエントリー資格がない**、という自己言及的ガバナー
- 振幅 < d までdを広げれば物理的に刺さらなくなる → 動的dの下限はチョップ実測振幅で決める

**制御**:
1. **決済数連動エントリー制限（中核）**: 直近 W 分間の利確数 C に対し、新規約定許容数 `E_max = base + α×C`。回転が止まれば新規が自然停止する（起動直後は base 分のウォームアップ）
2. **交互パターン即時検知**: 色系列が「BSBS」（2往復）成立で R4 確定 → 新規stop撤去 or d を実測チョップ振幅×1.3 に拡大
3. **ロックペア数上限**: ヘッジペア数 n_pair の上限を予算から逆算（`n_pair_max = チョップ予算 / (d+2c)`）。到達で完全停止＋間引きモード
4. **アンカー休眠**: R4確定後はアンカー更新を停止し、グリッドを「最後の推定レンジ外側」にのみ設置（= ブレイクアウト待ち伏せ配置）。チョップ内部では一切約定させない
5. **チョップ中の間引き優先度逆転**: チョップ中は滓の救済（トレンド）が来ないため、S1と逆に**確定損での間引きを積極化**してよい。ただしペアの片割れだけを外すとデルタが立つので、**ペア単位で外す**（両建て同時クローズ＝損失確定だが盤面が軽くなる）か、ペアのまま放置（追加損失ゼロ）かの二択。原則: 予算があればペア確定→盤面軽量化、なければ放置（ロックは増えない）

### S5: ボラ収縮（R5）

**想定する状況**: 振幅 < d。約定ゼロ。ポジゼロなら無害、滓持ちならキャリーコストだけ発生。

**仮説**:
- ボラ収縮はブレイクの前兆（ボラティリティ・クラスタリング）。**次のS7a（ブレイク）への準備期間**として使う
- 静穏時は滓の含み損が動かないため、**処理コストが最も読みやすい清掃時間**でもある

**制御**:
1. d の縮小（感度上げ）は R4 移行リスクと裏腹 → 縮小は「直近R4の実測振幅 × 1.3」を下限としてのみ許可
2. 滓・ペアの計画的清掃（予算内）。スワップ3倍日・週末・大型指標前はここで盤面を軽くしておく
3. ブレイク待ち伏せ: 収縮レンジの外側 ±1d に stop を維持（本仕様のまま）。**収縮検知時のみロット係数 1.2〜1.5 を許可**（ブレイク初動の期待値が最も高い場所のため）— ただし口座ゲート（セクション5.4）通過が条件

### S6: ボラ爆発・ギャップ・スパイク（R6）

**想定する状況**: 指標（NFP/CPI/FOMC）、フラッシュクラッシュ、週末ギャップ（XAU）、薄商い急変（BTC深夜）。複数stopが连続約定し、スリッページ拡大。**最悪パターンは「スパイク往って来い」: ピラミッドが頂点で積まれ、全ポジが瞬時に含み損化＋逆側stopも約定**。

**仮説**:
- stop注文は構造的に「踏まれる」側（ギャップはstopを飛び越えて滑る）。指値グリッドと違い、**R6は本戦略にとって機会ではなくテールリスク**（トレンドとして続けば利益だが、往復なら最大被弾）
- スパイクの判定は事後では遅い。**tick速度（単位時間tick数×平均変位）の異常**が唯一のリアルタイム前兆
- 予定イベント（指標カレンダー）は唯一の「合理的な外部フィルター」（参考テキスト: 安易なインジフィルターは機会を潰すが、合理的フィルターは残せ）

**制御**:
1. **イベントカレンダーゲート**: 高インパクト指標の前 T1 分〜後 T2 分は新規停止。盤面が重い場合は事前にグロス縮小（ペア確定や部分決済で証拠金余力を確保）
2. **tick速度ゲート**: tick速度が平常の n 倍（例: 3倍）超で新規stop発注を停止し、既存stopの距離を倍化
3. **約定レート制限**: 1分間に m 個以上約定したら以降の補充stopを停止（スパイク連鎖積みの遮断）
4. **スパイクタグ**: R6中に成立したポジは「異常エントリー」タグを付け、通常TPではなく**ブレイクイーブン近傍での早期撤退**を優先（往って来いの頂点掴みを軽傷で逃がす）
5. 週末ギャップ（XAU）: 金曜クローズ前に (a) 新規停止、(b) ペア・滓の清掃、(c) ネットデルタを0付近へ。BTCは24/7なので週末リスクは低いが、**土日の低流動性チョップ**にはセッションフィルターで対応

### S7: レジーム遷移

#### S7a: レンジ→トレンド（ブレイクアウト）— 「一気に解消」のゴールデンタイム

**想定する状況**: R3/R4/R5 で溜めた盤面が、一方向ブレイクで急変する。**上方ブレイク時: レンジ上部に堆積していたbuy滓は全て救済（含み益化）、下部のsell滓は全弾被弾**。さらに新規buyピラミッドが利益を積み始める。

**仮説（解消条件の定式化）**:
ブレイク振幅 A、ネットデルタ D、ブレイク中の新規ピラミッド利益 G(A) として、盤面の一括解消（バスケットTP）が成立する条件:

```
D × A + G(A)  ≥  累積ロック損失 + 逆側滓の含み損 + 目標利益マージン
```

- **D がブレイク方向に正なら盤面は自走的に改善**する。D が逆なら G(A) だけが頼りで解消が遠い
- ゆえにレンジ中の制御目標は「**どちらにブレイクしても解消可能な盤面**」= |D| を小さく保ち、ロック累積を『想定ブレイク振幅で賄える額』以下に抑えること
- 解消の実行は**バスケット全決済**（盤面合計が動的目標到達で全クローズ→アンカー再設定→盤面ゼロから再開）

**制御**:
1. **バスケットTP（動的目標）**: 目標額 = `(累積ロック + 支払コスト累計) × (1 + r) + 固定マージン`。盤面構築に費やした実費＋必要利回りで毎ティック再計算
2. **バスケット・トレイリング**: 盤面合計益のハイウォーターマークから x%（または金額）押しで全決済発動。ブレイクが伸びる限り引っ張る
3. **全決済の中断機構**（参考テキストの実装と同一）: 多ポジの順次クローズ中に逆行して「最低確保ライン（目標の50%等）」を割ったら中断し、残存ポジで戦略再起動。**決済順序は含み損ポジから**（中断時に含み益ポジが手元に残り、再トレイルできる盤面になる）。CloseByが使えるペアは優先的にペアで消す（片道スプレッド節約＋順序リスク低減）
4. **全決済後の残ポジ確認**: 約定拒否・リクオートで残るポジを必ず再スキャン（参考テキスト「死体撃ちレベルで確認」）。盤面ゼロを確認してからアンカー再設定
5. ブレイク中の逆側stop: S1制御（距離1.5〜2dに拡張）を即適用し、ブレイク中の押しで新たな滓を作らない

#### S7b: トレンド→レンジ（失速）

**想定**: ピラミッド上部のポジ（最後に積んだ数個）が含み損化。利確間隔が伸び、tick速度低下。

**仮説**: トレイル化（S1制御1）が機能していれば被害はピラミッド上部1〜2個に限定。失速の検知は「利確レイテンシ（約定→TP到達の所要時間）の伸長」が最速

**制御**: 利確レイテンシが移動平均の x 倍を超えたら、ピラミッド上部から LIFO で建値±0決済（伸ばすのを諦め、滓化する前に逃がす）。S1→NORMALへモード降格

#### S7c: V字反転 — 第2の死因

**想定**: フルに積んだピラミッドが頂点で急反転。全ポジ急速含み損化＋逆方向stopが連続約定開始。

**仮説**:
- バスケット・トレイリング（S7a制御2）が第一防衛線。**盤面合計のピークからのドローダウンで機械的に全決済**していれば、V字は「利益の一部返上」で済む
- 第二防衛線は反転で約定する逆方向ポジ自体（自動的にデルタを殺すヘッジとして機能する）。ただしこれを「ヘッジだから安心」と放置すると全部ロックに変わる — ヘッジ約定は時間稼ぎであり、稼いだ時間で何をするかが本体

**制御**:
1. 盤面トレイリングの発動を最優先（他のすべての決済ロジックに優先）
2. 盤面含み益がピーク比 x% 減で、逆方向stopのロット係数を一時的に引き上げ（デルタ中和の加速）— ただしロック化の加速でもあるので、係数上限 1.5、かつ直後にバスケット縮小決済（中和できた時点で両側まとめて決済し小さく逃げる）
3. V字確定後（逆方向ラン L≥3）は、旧ピラミッド側を「滓の層」として S2/S3 の清掃機構に引き渡す

## 4. 盤面（インベントリ）状態別: 想定 → 仮説 → 制御

市場レジームと独立に、盤面そのものが要求する制御がある。**同じレジームでも盤面が違えば正解は違う**。

### 4.1 ネットデルタの偏り（|D| 大）

**想定**: 例 B=10, S=3, 価格下落中。buy 10個が含み損、sell 3個が含み益。

**仮説（ポジションの役割非対称性 — 参考テキストの核心的指摘）**:
- **多数派 = トレンドベット、少数派 = 保険（ヘッジ）**。損益符号ではなく役割で扱いを変える
- 少数派の含み益を普通に利確すると、盤面は裸のロング10になり下落の全打撃を受ける。**少数派含み益ポジは利確対象ではなく保有対象**
- 「複数の含み損を1つの含み益で補う」方式は比率をさらに崩し、不利方向ナンピンと等価になる（参考テキストの警告）。ペアは原則1:1

**制御**:
1. **少数派保護ルール**: 少数派ポジの決済は「同時に多数派の含み損を1個以上ペア相殺できる場合」のみ許可（単独利確禁止）
2. **偏り連動エントリー**: |D| > n1 で多数派方向の新規を抑制、|D| > n2 (>n1) で停止。少数派方向はエントリー制限中でも例外的に許可（自然なデルタ中立化。参考テキスト「エントリー制限中にそれを許可するロジックで案外簡単に追従できる」）
3. **同方向ペア決済の解禁条件**: 異方向ペア（buy損+sell益）はグロス−2・デルタ不変。**同方向ペア（buy老損+buy若益）はグロス−2・デルタ−2**。よって |D| 過大時のみ同方向ペアを解禁し、デルタ縮小を優先する（参考テキスト「特定条件で相殺決済の条件を緩和（異方向→同方向も可）」の合理的解釈）

### 4.2 グロス過大（G 大・ヘッジ率高）

**想定**: チョップ通過後。ペアだらけで証拠金だけ食う「化石の地層」。

**仮説**: ペアの損失は確定済み（1.2節）なので、ペアを保持する唯一の理由は「決済コスト2回分の節約」と「業者のCloseBy優遇」のみ。**証拠金圧迫・管理複雑性と天秤にかけ、定期的に物理削除（ペア同時クローズ）すべき**。ロック会計を採用していれば、削除しても損益計算は1円も変わらない（心理的抵抗は会計が消してくれる）

**制御**:
1. グロス上限 G_max（証拠金から逆算）。超過時は「最も古いペア」から物理削除
2. CloseBy可能な業者ではペア成立の都度即CloseBy（片道スプレッド分得）。不可なら決済履歴を稼働ロジックに即時反映する補償処理（参考テキストの代替実装）
3. 証拠金使用率の4段階ゲート: <50% 通常 / 50-70% 新規ロット半減 / 70-85% 新規停止＋ペア削除強化 / >85% 強制縮小（最悪ペアから順次クローズ）

### 4.3 滓の層構造（価格帯別の含み損ポジ分布）

**想定**: 現在価格の上方に buy滓の層、下方に sell滓の層が点在（自分の取引履歴が作った等高線）。

**仮説**:
- 各滓の救済確率は「現在価格からの距離」に対して単調減少。**遠い滓ほど救済期待値が低く、間引き優先度が高い**
- 滓の密集帯は過去のレンジ端の写像であり、**将来の反転候補帯**としても情報価値がある（自己盤面 = 無料のボリュームプロファイル）
- 「現在の価格帯におけるポジションの置き方」（設計目標①）は、この層構造を見て決める: 滓密集帯に向かう方向の新規は抑制（そこで反転してきた歴史があるから）、滓の薄い方向への新規は通常運転

**制御 — 間引きスコアリング（設計目標②の中核）**:

```
score_i = w1 × (距離_i / ATR)        … 遠いほど処理
        + w2 × (滞留時間_i / T_ref)   … 古いほど処理
        + w3 × offside_i             … 多数派側の損ポジなら加点（処理でD改善）
        − w4 × hedge_value_i         … 少数派なら減点（保険価値、処理抑制）
        + w5 × carry_i               … スワップ/ファンディング負担が重いほど処理
```

- 間引き実行は score 上位から、**間引き予算**（= 実現利益 × β + ペア決済で浮いた額）の範囲内のみ
- 予算制の意味: **実現損益カーブを右肩上がりに保ったまま掃除する**（「必要経費が大きくなりすぎて現実的な利確が遠のく」の防止を会計的に保証）
- 予算不足時の補助ルール: (a) 滞留 T_max 超は予算外で強制処理、(b) 処理できない大物は反対ポジでロック化（損失拡大の凍結）→ 4.2の地層管理へ移管

### 4.4 「実現+ロック」勘定とリセット制度

**仮説**: グリッド系の破滅は「リセットできない心理」から来る。**リセットを機械化した者だけが生き残る**

**制御**:
1. 3勘定管理: ①実現損益 ②ロック損益（確定扱い） ③純粋含み損益（滓のみ）。健全性指標は「①+② の水準」と「③の対利確ペース比」
2. **回収倍率** = 盤面含み損合計 / 直近平均利確ペース（時間換算）。「今のペースであと何時間分の利益が滓処理に必要か」。例: 48hで間引き強化、96hで新規停止、144hで盤面リセット検討
3. **盤面最大投資額** = 口座の x%（例5%）。「①+②のドローダウン」が到達したら**全決済リセット＋クールダウン＋パラメータ再導出**。最悪ケースを口座の x% で構造的に有界化する。これが「小さく死ぬ」制度

## 5. 制御モジュールカタログ（実装単位）

### 5.1 エントリー制御（8種）

| # | モジュール | 内容 | 主対象レジーム |
|---|---|---|---|
| E1 | 決済数連動ガバナー | `E_max = base + α×C`（直近W分の利確数C） | 全域（中核） |
| E2 | 偏り連動 | 多数派抑制・少数派緩和（4.1） | R2-R4 |
| E3 | 動的グリッド幅 d | 直近N期間のATR/Renko実測から導出。下限=チョップ実測振幅×1.3、下限=業者ストップレベル | 全域 |
| E4 | 非対称グリッド | トレンド時: 順方向d / 逆方向1.5-2d | R1, S7a |
| E5 | tick速度ゲート | 異常時は発注停止・距離倍化 | R6 |
| E6 | イベントカレンダー | 高インパクト指標前後の停止（唯一の外部フィルター） | R6 |
| E7 | 証拠金ゲート | 4段階（4.2） | 全域 |
| E8 | スプレッドゲート | スプレッド拡大時は新規停止（TP=k×2cの定義が崩れ、回転が死ぬため） | 早朝・指標時 |

### 5.2 決済制御（8種）と優先順位

| 優先 | モジュール | 内容 |
|---|---|---|
| 0 | 盤面トレイリング | ハイウォーターマークからの押しで全決済（V字防衛、全てに優先） |
| 1 | バスケットTP | 動的目標到達で全決済→リセット（中断機構・死体撃ち付き） |
| 2 | ペア決済（異方向1:1） | 合計+ε以上で即実行。CloseBy優先。少数派保護ルール適用 |
| 3 | 同方向ペア決済 | \|D\|過大時のみ解禁（デルタ縮小用） |
| 4 | 単ポジトレイル | R1中の新規・含み益ポジ |
| 5 | 単ポジTP | 基本回転（k×2c）。kはスプレッドの2〜10倍を確保（meanprofitが低いとスリッページに食われる — 参考テキスト） |
| 6 | 時間・イベント決済 | スワップ3倍日前、週末前、滞留T_max超 |
| 7 | 間引き | スコア順・予算内（4.3） |

優先順位の思想: **盤面全体のリスクゼロ化（0,1）＞盤面改善（2,3）＞利益伸長（4）＞基本回転（5）＞掃除（6,7）**。複数条件同時成立時は上位が下位をプリエンプトする。

### 5.3 TP/d 比率 ρ の設計（基本性格の決定）

| ρ | 挙動 | 向き |
|---|---|---|
| ρ < 1 | 各ポジは次ブリック前に利確。同時保有少・盤面軽量・回転型。トレンドの尻尾は捨てる | NORMAL |
| ρ ≈ 1 | 利確と増し玉が同期 | 過渡 |
| ρ > 1 | 複数ポジ同時含み益で進行（真のピラミッディング）。盤面重・伸長型 | TREND（トレイル化が上位互換） |

推奨: **NORMALは ρ=0.6〜0.8 の回転型、TREND検知でトレイルに切替**（固定の大きいρより、検知後トレイルの方がチョップ被弾と尻尾捕獲の両立で優位）。

### 5.4 ロット設計

- **均一ロットが基本**（倍増マーチンは S7c で破滅を加速する）
- 上限の逆算: `最悪チョップ持続往復数の95%ile × (d+2c) × ロット ≤ チョップ予算`
- モード係数: TREND順方向 1.0〜1.3 / ボラ収縮ブレイク待ち伏せ 1.2〜1.5 / CHOP 0
- 業者対策: 1注文の上限ロットで滑り出す場合は分割発注（参考テキスト: 5lot以上で滑る→4lot並列）

## 6. 統合戦略 — 状態機械（モード）アーキテクチャ

### 6.1 レイヤー構造

```
L5 リスク層     証拠金・イベント・異常検知。全レイヤーへのオーバーライド権限
L4 レジーム推定層 自己約定列・利確回転・tick速度から R1-R7 を推定
L3 決済層      5.2の優先順位エンジン
L2 盤面管理層   D/G/層/ロック/回収倍率の常時計測
L1 エントリー層  グリッド生成（動的d・非対称・アンカー管理）＋ 5.1ゲート群
L0 実行層      発注・約定管理・残ポジ確認・リトライ・スリッページ計測
```

### 6.2 モード定義と遷移

| モード | 概要 | 主な有効モジュール |
|---|---|---|
| NORMAL | 基本回転（ρ<1） | E1-E3,E7,E8 / 決済2,5,6,7 |
| TREND | 伸長・救済 | E4追加 / 決済0,2,4 優先、間引き抑制 |
| CHOP | 防御 | 新規停止 or d拡大 / ペア物理削除、待ち伏せ配置 |
| EVENT | 退避 | E5,E6発動 / 新規停止、事前グロス縮小 |
| RECOVERY | 一括解消 | 決済0,1 実行中（中断機構あり） |
| HALT | 異常停止 | 整合性エラー・証拠金85%超・接続断。人間にアラート |

**遷移条件（すべて自己観測量で定義 — 外部インジ不使用）**:

```
NORMAL → TREND   : 同色ラン L≥3 かつ 利確回転増加 かつ tick速度>平常×1.5
NORMAL → CHOP    : 交互色2往復 or W分間利確ゼロ or ロックペア増加率>閾値
TREND  → NORMAL  : 利確レイテンシ>移動平均×2 or 順方向約定途絶X分
CHOP   → NORMAL  : d拡大後の新規約定がレンジ外で発生＋回転再開
any    → EVENT   : カレンダーT分前 / スプレッド異常 / tick速度異常
any    → RECOVERY: 盤面合計 ≥ 動的バスケット目標
RECOVERY→NORMAL  : 全決済完了（盤面ゼロを死体撃ち確認）→ アンカー再設定
any    → HALT    : L0整合性エラー / 証拠金>85% / 接続断
優先度: HALT > EVENT > RECOVERY > CHOP > TREND > NORMAL
```

### 6.3 「自己約定列 = 市場センサー」という設計思想（参考テキストの体系化）

外部インジケーターでレジームを推定するのではなく、**自分のグリッドへの市場の応答**を観測量とする:

| 観測量 | 推定対象 |
|---|---|
| 約定色系列のランレングス分布 | P(継続) のオンライン推定 → E[L] → エッジ生死判定 |
| 利確回転数（直近W分） | ロジック適合度（E1ガバナーの入力） |
| 利確レイテンシ | 実効ボラ・失速検知 |
| 約定スリッページ | 流動性状態（R6前兆） |
| 自己滓の層分布 | レンジ端・反転候補帯 |

利点: (a) 遅延ゼロ（インジは確定足待ちが多い）、(b) スプレッド・スリッページ込みの**実効値動き**を直接反映、(c) パラメータが市場でなく「自分の戦略の機能状態」を測る — 参考テキストの「過去データは参照しない。『今』と自身が行った事象からアプローチ」「ほぼ全てのパラメータを動的にし、エントリー結果・保有ポジの損益情報や比率からリアルタイム最適化」の実装形。

## 7. 商品選択: BTCUSD vs XAUUSD

| 観点 | XAUUSD | BTCUSD (MT5 CFD) |
|---|---|---|
| ギャップ | 週末ギャップあり（stopが飛ぶ＝本戦略の急所） | ほぼ無し（24/7）— **構造的に有利** |
| コスト/ボラ比 | 業者によるが一般に良好 | スプレッド・スワップが重い業者が多い |
| セッション構造 | アジア静・欧米動で読みやすい（フィルター化容易） | 深夜・週末の薄商いチョップが長い |
| イベント | 指標カレンダーで管理可能 | 24/7突発（規制・清算カスケード） |
| トレンド頻度×振幅 | 2024-26は強上昇でE[L]非対称（buy>sell） | 高ボラだがチョップ期間も長い |
| 業者制約 | CloseBy・ストップレベル要確認 | 同左＋最小ロット刻み要確認 |

**判定基準（実測で決める）**: 両商品の tick データを d-Renko 化し、`E[L] − 1 − (d+2c)(1−η)/(ρd−2c)` を時間帯別に計測。**コスト正規化したランレングス余剰が大きい方**を採用。直感ではギャップレスのBTCが構造適合だが、コストの重さで逆転しうる。XAUを選ぶ場合、上昇バイアスを認めて buy/sell に非対称パラメータ（sell側のグロス上限小・間引き速め、またはD中心を+nへオフセット）を持たせる。

## 8. MT5実装の実務注意

1. **ヘッジングモード口座必須**（ネッティングでは両建て盤面が成立しない）
2. **ストップレベル/フリーズレベル**: 動的dの下限は `SYMBOL_TRADE_STOPS_LEVEL + マージン`。違反は発注拒否（参考テキストでも稼働停止事故）
3. **アンカーは理論グリッド価格基準**（約定価格基準だとスリッページでグリッドが歪み累積する）。実約定とのズレはスリッページ統計として別途記録
4. **stop再設置の節流**: アンカー更新毎の注文修正が高頻度になると業者に締められる（tick毎のSL修正は怒られる — 参考テキスト）。修正は秒間上限を設ける
5. **CloseBy対応の確認**: 非対応業者では「両ポジ同時決済発注＋決済履歴の稼働ロジックへの即時反映」で代替
6. **全決済の執行設計**: 順次クローズ中の価格変動を前提に、(a)損ポジ優先 (b)ペアはCloseBy (c)最低確保ライン割れで中断、を実装
7. **死体撃ち**: 全決済後・部分決済後のポジション再スキャンを必ず実行（約定拒否・リクオート残り）
8. **接続アーキテクチャ**: 推奨は **MQL5 EA = L0実行層（約定反応・死体撃ち・ゲート）、外部Python = L2-L5頭脳（盤面分析・レジーム・パラメータ導出）** のハイブリッド。Python MT5公式APIの長時間接続は不安定（参考テキスト: 全TCP移行）。VPS/クラウドでの自動復帰（再起動後に盤面を取引履歴から再構築する resync 処理）を初期から設計
9. **多重起動ガード**: 同一口座への二重稼働は盤面管理を破壊する（参考テキストでも事故報告）。ロックファイル＋マジックナンバー分離

## 9. 検証計画（実装前にやるべき順序）

### Phase 1: d-Renko 統計分析（コード500行・最重要）
tickデータ（両商品×3ヶ月以上）を d-Renko 列に変換し:
- ランレングス分布（時間帯別・セッション別・d別）
- `E[L]` の時系列とレジーム持続時間分布（チョップの95%ile持続往復数 → 予算とロット上限の根拠）
- マスター方程式の損益分岐を満たす (商品, 時間帯, d) の組を特定
**この分析だけで「どこで回せば勝てるか」が実装前に分かる。**

### Phase 2: イベント駆動バックテスト
- tickベース・変動スプレッドモデル・スリッページモデル（約定価格=stop価格+片側ノイズ）必須。M1 OHLCは本戦略では嘘をつく
- 検証する不変量: ロック累積カーブ、バスケットTP到達分布、最大証拠金使用、回収倍率の分布
- **パラメータは固定最適化しない**（動的導出ロジックごと検証する。「バックテストでパラメ固定する案件ではない」— 参考テキスト）

### Phase 3: 合成データ・モンテカルロ
- レジーム切替型の合成価格（Markov切替ランダムウォーク）で「チョップがX時間続いた場合」の損失分布をパラメトリックに掃く
- 実データに存在しない最悪系列への耐性確認（リセット制度が機能するか）

### Phase 4: フォワード（最小ロット・実口座）
- 目的はロジック検証ではなく**実行系の検証**: 実スリッページ、stop再設置の業者反応、CloseBy挙動、死体撃ち、再起動resync
- 可視化ダッシュボード（価格チャート＋全ポジ線＋equity＋B/S統計＋モード遷移ログ）を同時に作る。コミュニティ全員が自作している理由: **多ポジ戦略は可視化なしでは一要素変更の影響が人間に理解できない**

## 11. 未決定の設計分岐 — 壁打ち議論ポイント

1. **基本性格**: NORMAL を回転型（ρ<1）とする本書の推奨でよいか。それとも常時ピラミッディング（ρ>1）で盤面を重く持つ思想か
2. **反転幅の非対称化**: 仕様③のアンカー対称グリッド（1d反転）を、常時 or トレンド時のみ 1.5-2d 反転（標準Renko化）に変えるか。チョップ被弾と反転初動の遅れのトレードオフ
3. **ロック会計**: ヘッジペア損失を発生時点で実現扱いする会計（1.2節）に同意するか。これは間引き・リセットの全意思決定の前提になる
4. **リセット制度**: 「盤面最大投資 = 口座x%で機械的全決済リセット」の x を決める（推奨3-5%）。これが事実上の戦略の最大DD定義になる
5. **商品**: Phase 1 の実測で決める方針でよいか。XAU採用時の buy/sell 非対称パラメータの是非
6. **実装形態**: MQL5単体 vs MQL5(L0)+Python(L2-L5)ハイブリッド。開発速度と実行レイテンシのトレードオフ
7. **検証順序**: Phase 1（d-Renko分析）を最初の成果物とすることに同意するか。ここで数字が出なければ実装自体を再考すべき
